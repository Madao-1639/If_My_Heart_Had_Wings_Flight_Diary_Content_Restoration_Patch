# 国外补丁逐处核验协议（逐条核对）

> 状态图例：✅ 已确认 ／ ⚠️ 部分确认 ／ ❓ 未知
> 本文规定**怎么核验第三方补丁的每一处改动**，判据与交付格式。核验结论记入
> [third-party-patch-analysis.md](third-party-patch-analysis.md) §2.6。
> **红线：不把补丁当蓝本**——每一处改动都要独立判定「是否真是原版↔Steam 的语义分歧点」+「改动是否真的还原了原版内容」。

---

## 0. 为什么不能只看条数

`0x14`（对白）条数相等**只能证明文本量对上了**，证明不了：

- **演出与台词是否配对**：把台词汇入脚本却没把对应的 CG 显示 / 立绘 / 语音 / 特效指令一并带入 ⇒ 台词与画面对不上（**本补丁已知存在此问题**）。
- **语音是否漂移**：语音指令（`0x28` 带 `char*` 槽 / `0x2e`）与它那一句严格绑定；插入台词汇而不迁移语音指令 ⇒ 语音漂到下一格。
- **跳转是否自洽**：绝对偏移（`0x01`/`0x02`/`0x06`）是否重定位。
- **成就触发点是否补齐**：CG 显示点是否都带 `CG_ACHIEVEMENT`。

⇒ **必须逐条（指令级 + 序列级）核对。**

## 2. 判据（逐条）

对补丁改过的每一个脚本，做以下五项：

### V-1 演出序列对齐（顺序敏感）
把 ORIG / STEAM / PATCH 的演出资源序列（`res_seq.py --dump`）做**序列比对**（LCS / difflib）。
- **通过**：PATCH 在还原区间内与 ORIG **顺序一致**（不只是数量一致）。
- **不通过**：数量一致但**顺序**与 ORIG 不同（说明是重新拼的），或与 STEAM 一致（说明演出没还原）。

### V-2 缝合边界定位
找出 PATCH 序列中「与 ORIG 一致」与「与 STEAM 一致」的**切换点**，即补丁把原版块缝进来的边界。逐一记录边界偏移。
- 边界必须落在**指令边界**上（用 `ws2fmt` 在 PATCH 上验证）；落在指令中间 ⇒ 结构性错误。

### V-3 演出↔台词配对（核心）
在**还原区间内**，逐条检查 PATCH 的指令流：
- 每条 `0x14` 是否都有 ORIG 对应的**前置演出**（背景/立绘 `0x33`/`0x34`/`0x39`、图层 `0x46`、特效 `0x44`–`0x48`、`0x65`）；
- 每条该有语音的 `0x14` 是否都带对应的**语音指令**（`0x28` 且槽名为 `char*`，或 `0x2e`）；
- **台词与语音的条数比**是否与 ORIG 一致（ORIG 的「OGG 数 : 0x14 数」是基准）。
- **不通过**：台词数对上但 OGG 数不足 ⇒ **语音缺失/漂移**（补丁已知缺陷）。

### V-4 跳转与偏移自洽
- `0x07 NextFile` 目标是否与原版语义一致（是「还原」还是「硬接」）；
- `0x01`/`0x02`/`0x06` 的绝对偏移是否落在指令边界（用 `ws2fmt` 反汇编 PATCH 全程即可验证——能 100% 平铺即说明自洽）。

### V-5 成就触发点
还原区间内每个 CG 显示点（`0x34` PNA + 固有 id 对）后是否都有 `04 "CG_ACHIEVEMENT" 00`。

## 4. 已确认的补丁缺陷（先验 + 本轮实测）

> ⚠️ **D-6 已作废（2026-10-16 实测更正）**：D-6 曾把「补丁在缝合脚本里没注入 `CG_ACHIEVEMENT`」记为缺陷，并据此定下"还原区间每个 `0x33` 站点都补成就调用"的红线。**该结论不成立**：
> ORIG 与 Steam 的 CG 固有 id 对（`0x33` 后两条 `0x0b`）**交集为 0**（14 个脚本全为 0），按 ORIG 的 id 注入 `04 CG_ACHIEVEMENT` 是**空操作**；而 Steam 侧原有的 `0x0b`×2 + `04 CG_ACHIEVEMENT` 属 `KEEP_OPS`/非 `LAYER_ORDER` 调用 ⇒ 删格时天然被保留。⇒ **补丁不注入是对的**，本项目也已改为**不注入**，验收口径改为「产物 `CG_ACHIEVEMENT` 数 == Steam 原有数」。

### 判据修正（重要）✅

**本作 FD 的事件 CG 走 `0x33`（PNG）显示，不是 `0x34`（PNA）**。成就调用的挂点是：

```
33 <slot>\0 <FILE.PNG>\0 01 01  0b <u16 A> 01  0b <u16 B> 01  [04 "CG_ACHIEVEMENT" 00]
```

（`0x34` 的 PNA 显示在本作**不**带成就调用。）判据 V-5 必须按 `0x33` 站点统计。
