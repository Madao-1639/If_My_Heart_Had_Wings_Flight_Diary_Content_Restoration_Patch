## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 国外补丁是否"直接用原版脚本覆盖"？ | ❌ **不是**。它以 **Steam 的英文 `*_E.ws2` 为基线**，只把原版**日文 H 场景正文**缝进去；仅 2 个脚本（`AGS_001.ws2`、`KAN_3002_2.ws2`）用原版脚本 |
| 它的还原手段是什么？ | 三种：**同名脚本内缝合**（正文变大）／**跳转改指**（指向还原场景）／**整档换回原版素材**（CG/语音） |
| 它的 H 场景是什么语言？ | **日文原文**（未翻译）——与 Steam 英文正文混排 ✅ |
| 中文补丁的 `font.ttf` + `FONTCHANGER.dll` + `winmm.dll` + `hook.ini` 是否必要？ | ❌ **不必要**。这是**通用字体替换工具**（ALyCE FONTCHANGER），与文本注入无关；官方简中语言包已自带含汉字字形的 `Fonts.arc` |
| 中文补丁为什么不用原生 `.lng` 通路？ | 因为国外补丁**改了 ws2 的正文槽位数**，`.lng` 的**按位置对应**被破坏；作者只能把中文**直接写进 ws2 窄字节**（CP932），代价是只能写 Shift-JIS 有的字（简繁日混用、字形错位） |

⇒ **本项目不沿用这两套做法**：以 Steam 脚本为基线做**指令级还原**，中文走**原生 `zh-CN/Rio.arc` 的 `.lng` + `NameTable.txt`**，并在每次增删正文后**整体重建 lng**（见 [restoration-route.md](restoration-route.md)）。

## 2. 国外还原补丁：它到底改了什么 ✅

### 2.2 剧本（`Rio.arc`，115 成员）

| 动作 | 对象 | 证据 |
|---|---|---|
| **新增原版脚本** | `AGS_001.ws2`、`KAN_3002_2.ws2` | 与原版同名脚本**内容不同**（161898 vs 152066；60507 vs 57665）——差值是**注入的 `CG_ACHIEVEMENT` 成就调用** |
| **同名缝合** | `AFT_003_E`、`AFT_007_3_E`、`BEF_003_E`、`BEF_004_E`、`HOT_002_E`、`HOT_004_E`、`HUS_001_E`、`KAN_3001_3_E`、`KAN_3001_4_E`、`KAN_3002_1_E` | 跳转结构**不变**但体积显著变大（如 `AFT_003_E` 99038→153080，新增 **501 条日文行**；`HOT_002_E` +35 KB） |
| **跳转改指** | `KAN_3002_1_E` | `0x07 NextFile` 由 `KAN_3002_2_E`（Steam 全年龄替代场景）改为 `KAN_3002_2`（还原的日文 H 场景） |
| **入口硬接** | `HUS_001_E` | 尾跳由 `TITLE` 改为 `AGS_001`（把 AGS 线硬接到 HUS 线结尾） |
| **CG 画廊** | `CG_PAGE01…04` | 体积约翻倍，为还原的 CG 补页码条目 |

**缝合内容的语言 = 日文原文**：`AFT_003_E` 新增的 501 条全是日文台词（如「小鳥の足の指、可愛いな。」），**未翻译**。⇒ 玩家会在英文正文里读到整段日文 H 场景。

> **缝合策略逐脚本不同**（逐条核对实测）：
> 1. **尾部大块缝合**（Steam 基底 + 原版块）：`HOT_002`/`HOT_004`；
> 2. **多段散布缝合**：`HUS_001`（缝合点散布在 PATCH 的 `0xd48a`/`0xf48d`/`0x11602`… 等 10 处）；
> 3. **整脚本换原版内容**（再按本作引擎格式**重新编码**）：`KAN_3001_3`（正文 483/483 条台词全部来自 ORIG，0 条来自 STEAM）、`AGS_001`、`KAN_3002_2`。
>
> 且**不是逐字节复制**：ORIG↔PATCH 的最长公共字节段只有 24–389 B（覆盖率 17–27%）——补丁作者是按本作引擎格式**重新编码**的（只有日文串本身逐字节相同）。
> ⇒ 这对本项目是**好消息**：说明「原版内容 → 本作引擎」的转码是可行的，且补丁提供了一份可参照的对应关系。

### 2.7 `AGS_001.ws2` 的转换偏差 ✅（可作 L1 蓝本，但**不能照抄**）

补丁的 `AGS_001` **不是「原版块 + Steam 块」缝合**（Steam 根本没有 `AGS_001` 可缝），而是把原版整脚本**重新编码进 Steam 格式 + 注入成就 + 顺带改了一批取值**。
指令级核对：`0x14` **1121 = 1121**、OGG **442 = 442**、`0x28`/`0x2e` 434/427 相同、`0x33`/`0x34` 216/179 相同、演出序列 852 条**逐条同序同名**、`0x07` 尾跳 `EVRET`/`TITLE` 与原版一致（**非硬接**）、147 个 CG 显示点的成就 **147/147 无漏无多**。

**但存在 7 类转换偏差（均为补丁自行引入，非原版↔Steam 分歧点）：**

| # | 偏差 | 量级 |
|---|---|---|
| A-1 | 每条对白**多插一条空 `0x15`**（`15 00 00`，清名框） | `0x15` 1121 → **2242**（+1121） |
| A-2 | `0x46` 图层 u8 参数 `128`→`240` | 168 处 |
| A-3 | `0x47` 特效整型 `128`→`192` | 34 处 |
| A-4 | `0x39` 参数 `39`→`31` 等 | 7 处 |
| A-5 | 说话人名 token 日文→罗马字（`あげは`→`Ageha` 等） | 635 处 |
| A-6 | 对白正文内 `碧`→`Aoi` | 57 处 |
| A-7 | `0x14` 的 u32 序号 **+1**（`0..N-1` → `1..N`） | 全部 |

> A-5 是**必要**的（`NameTable.txt` 的 key 是罗马字，见 D-8/D-13）；A-7 无害但无必要；
> **A-1/A-2/A-3/A-4 是纯改动**——按 §2.7 的机械规则搬运（只补 7 个 opcode 的尾部字段）就**不需要**它们。
> ⚠️ **A-1 待实机确认**：若「每条对白前清一次名框」在 Steam 引擎下确为必要（名字框继承语义差异），则必须保留；否则不要引入。

**本项目采用**：✅ 采用其**正文与演出序列**（忠实原版，可作 L1 蓝本）+ **147 处成就注入做法**（位置正确，可直接复用）。
❌ 不采用 A-1/A-2/A-3/A-4/A-7；跨版本搬运走**两表差异的机械规则**（[route-mechanics.md](route-mechanics.md) §5.1）。

## 3. 中文汉化补丁：做了什么 ✅

### 3.1 文件构成

| 文件 | 结论 |
|---|---|
| `hook.ini`（165 B） | FONTCHANGER 的配置：`LOADDLL=FONTCHANGER.dll`、`FONTNAME=font`、`FONTFILENAME=font.ttf`、缩放 100% |
| `winmm.dll`（51 KB） | **DLL 代理劫持**：游戏加载 `winmm.dll` 时被替换，用于**加载 `FONTCHANGER.dll`**（`hook.ini` 的 `[GLOBAL] LOADDLL` 由它读取） |
| `FONTCHANGER.dll`（334 KB） | 第三方**通用字体替换工具**（ALyCE FONTCHANGER），**与文本注入无关**：只把引擎的字体请求重定向到 `font.ttf` |
| `font.ttf`（16.6 MB） | TrueType，`numGlyphs=29957`，覆盖简/繁/日；family 名 `font` |
| `zh-CN/Rio.arc`（584 KB） | **官方 `zh-CN/Rio.arc` 的真子集**：40 成员 vs 官方 50，且这 40 个**逐字节相同**；缺的 10 个恰是国外补丁改过的脚本（`AFT_003_E`/`AFT_007_3_E`/`BEF_003_E`/`BEF_004_E`/`HOT_002_E`/`HOT_004_E`/`HUS_001_E`/`KAN_3001_3_E`/`KAN_3001_4_E`/`KAN_3002_1_E`）。总条目 12359 vs 官方 17669 |
| `Rio.arc`（根，4.1 MB） | = 国外补丁 `Rio.arc` **再注入中文**：12 个脚本（被补丁改过的那些）的中文被**直接写进 ws2 窄字节**，编码 CP932/Shift-JIS |

### 3.2 关键判定

1. **字体三件套不必要** ✅：官方 Steam 版简中语言包已提供含汉字字形的 `zh-CN/Fonts.arc`（成员 `NotoSansCJKsc-Regular.PTF`，16 MB）与 `AdvHDLang.dll`。若安装目录保留官方语言包，**无需** `font.ttf`/`FONTCHANGER.dll`/`winmm.dll`/`hook.ini`。
2. **`.lng` 密钥 = `0x3E`** ✅（官方 `zh-CN/Rio.arc` 与中文补丁根 `Rio.arc` 实测一致，非 GalRev 记录的 0x2C/0xCE）。
3. **为什么不用原生 `.lng`** ✅：国外补丁改了正文槽位数 ⇒ 官方 `.lng` 的位置对应失效。作者改用**窄字节直写**，代价是**只能写 Shift-JIS 覆盖的汉字**：实测被替换为日文形的字有「総／覚／齢／沒／邊」，简体专用字（如「们／这／说」）写不进去。⇒ 质量与可维护性都劣于原生通路。
4. **中文补丁依赖国外补丁的脚本** ✅：它的根 `Rio.arc` 以国外补丁 `Rio.arc` 为基底，因此**继承了全部缝合、跳转改指与入口硬接**。

## 4. 对本项目的直接约束（方针）

1. **不采用"窄字节直写中文"**：中文一律走 `zh-CN/Rio.arc` 的 `.lng`（UTF-16LE，key `0x3E`）与 `NameTable.txt`；剧本 ws2 里的窄字节只保留 CP932 能表达的内容。
2. **不采用"整档换回原版素材"以外还要动脚本名"**：素材冲突一律**整名覆盖**（同 [resource-naming.md](resource-naming.md) 方针），脚本引用点按需改写。
3. **任何正文增删后必须整体重建 lng**（位置对应等式见 [restoration-route.md](restoration-route.md) 与 `doc/localization` 相关章节）。
4. **成就调用 `CG_ACHIEVEMENT` 必须原样保留**，新增/还原脚本也要补齐（见 [achievement-mechanics.md](achievement-mechanics.md)）。
5. **不触碰朱莉线**：`Rio1.arc`、`Chip10.arc`、`AKA_*`、`zh-CN/Rio1.arc` 保持 Steam 原样。
